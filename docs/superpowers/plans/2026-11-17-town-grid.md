# 동네 격자 골목 + 들어가는 가게 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 좌우 한 줄 동네를 큰길 + 뒷골목 2줄 + 샛길 격자(9열 × 3줄)로 바꾸고, 들어가는 가게 5곳(PC방·코인노래방·오락실·코인빨래방·카페)과 붕어빵 노점·버스정류장·동네 고양이를 넣는다.

**Architecture:** `Lot`에 줄 이동값(`zOff`)을 더해 지금 집·마당·울타리 계산을 줄마다 그대로 재사용한다. 칸 표(`SLOTS`)는 고정이고, 가게 칸을 뺀 집 칸을 내 집에서 가까운 순으로 채운다. 편의점 전용 코드(`cvs.ts`·`cvs3d.ts`·World의 `area === CVS` 분기)는 "가게 목록"(`lib/shops.ts` + `three/shops3d.ts`)으로 일반화하고, 새 가게는 항목만 추가한다.

**Tech Stack:** TypeScript, React 19, three.js 0.187, vitest

**Spec:** `docs/superpowers/specs/2026-11-17-town-grid-design.md`

## Global Constraints

- 커밋은 사용자가 직접 한다 (CLAUDE.md). 각 작업 끝의 "확인"은 `npm test` + `npx tsc -b` 통과까지.
- 단위 m, x 동쪽, z 남쪽. 모든 집·가게 문은 남쪽(길 쪽).
- 같은 방 목록 → 모든 화면에서 같은 배치 (난수 금지, `hash01`만).
- `AreaId` `'cvs'`는 이름 유지. 새 가게 area: `'pc' | 'sing' | 'arcade' | 'laundry' | 'cafe'`. 가게 안 누름 key 접두: `<가게id>/`.
- 실제 노래·가사 금지 (노래방은 가짜 곡 제목 + 효과만).
- 주석·문구는 지금 코드처럼 쉬운 한국어.

## Review Focus

1. 집 17채 꽉 찬 동네와 1채 동네 모두에서 모든 대문·가게 문·뒷산·방파제까지 길이 있다 → Task 1 테스트 `모든 문까지 걸어간다`.
2. 친구 1명 추가 시 기존 집 자리가 안 바뀐다 → Task 1 테스트 `친구가 늘어도 원래 집은 제자리`.
3. 가게 안 모든 누름 자리까지 들어온 자리에서 걸어갈 수 있다 → Task 3/4 테스트 `가게 안 모든 자리까지 걸어간다` (가게 목록 전체를 도는 한 테스트).
4. 실시간으로 받은 area 값 검사: 새 가게 id는 받고 이상한 값은 버린다 → Task 3 테스트 `isArea`.
5. 고양이 자리는 같은 시각이면 어느 화면에서나 같고, 늘 막히지 않은 곳이다 → Task 5 테스트 `고양이`.

### Task 1: 격자 배치 데이터 · 막힌 곳 · 길찾기

**Files:**

**Interfaces:**
- Produces:
  - `ROW_PITCH = 16`, `ROWS = 3`, `COLS = 9`, `ALLEY_W = 4`, `STREET_W = 4`
  - `colX(c: number): number` — c ∈ −4..4, `c*13 + (c>=2 ? 4 : c<=-2 ? -4 : 0)`
  - `rowOff(r: number): number` = `-r * ROW_PITCH` (0, −16, −32)
  - `interface Slot { row: number; col: number; x: number; zOff: number }`
  - `SHOP_SLOTS: Record<ShopId, { row: number; col: number }>` = cvs(0,−2) pc(0,2) arcade(1,−3) cafe(1,3) sing(2,0) laundry(2,−4)
  - `houseSlots(): Slot[]` — 가게 칸을 뺀 24칸, 내 집 칸(0,0)부터 (x,z) 거리순, 같으면 x 작은 순 → z 큰 순
  - `Lot` += `row: number; col: number; zOff: number`
  - `layoutLots(roomIds)` — i번째 방 → `houseSlots()[i]`, 최대 17
  - `emptySlots(lots: Lot[]): Slot[]` — 집도 가게도 없는 칸
  - `STREET_X = [-21.5, 21.5]` 샛길 가운데 x; 격자 양 끝 길: `GRID_W = colX(4) + 6.5 + 4` (= 66.5)
  - `Zones` 고정: `hw = -GRID_W`, `he = GRID_W`; `storeX/storeStep` 제거 → `shopDoor(id): Vec2`(문 앞 골목 쪽), `shopRect(id)`
  - `doorStep/gateSpot/mailboxSpot/yardRect/fenceSegments`는 `lot.zOff`만큼 z 이동
  - 가게 건물: 가운데 x = 칸 x, 앞면 z = `FENCE_Z + zOff - 2.4`, 크기 `STORE_W × STORE_D`, 문 x = 가운데 + `STORE_DOOR_DX`
  - `townBounds`: `minZ = rowOff(2) + HOUSE_BACK_Z - 3` (−51), 나머지 같음
- `blocked` 규칙(위에서부터):
  1. 바깥 경계, 바다(지금과 같음)
  2. 격자 안(`hw ≤ x ≤ he`): 뒷줄 뒤(`z < rowOff(2)+HOUSE_BACK_Z-1`) 막힘. 각 칸(집·가게·빈 칸)의 띠 `z ∈ [back-1, front]`, `|x-칸x| < LOT_W/2` 막힘 (front = 집이면 HOUSE_FRONT_Z+zOff, 가게면 건물 앞면, 빈 칸이면 HOUSE_FRONT_Z+zOff). 집 울타리·우편함·가게 건물 막힘.
  3. 격자 밖: `z < HOUSE_BACK_Z - 1` 막힘, 뒷산 안쪽만 열림 (지금과 같음)
- 장소 위치: 뒷산 `hill.x = hw - 16`, 포장마차 `pocha.x = hw - 8`, 바닷가 계산식 그대로(`he` 기준).
- 편의점 앞 소품(파라솔·자판기·분리수거함)은 편의점 칸 기준으로 옮긴다.
- 빈 칸 소품: `{ kind: 'lotsign', x: 칸x + 2.6, z: FENCE_Z + zOff - 1.2, r: 0.25 }` + 꽃·덤불 2~3개.
- 뒷골목 가로등: 각 골목 북쪽 가장자리를 따라 13m 간격 `lamp`.

- [ ] **Step 1: 실패하는 테스트 작성** — 옛 `slotX`·편의점 위치 테스트를 아래로 바꾼다:
  - `칸 표`: `houseSlots()` 길이 21, 첫 칸 `{row:0,col:0,x:0,zOff:0}`, 둘째·셋째는 `col ±1, row 0`, 넷째는 `{row:1,col:0}`; 가게 칸은 없다.
  - `친구가 늘어도 원래 집은 제자리`: `layoutLots(ids.slice(0,5))`의 각 lot이 `layoutLots(ids)`에서도 같은 x·zOff.
  - `집은 최대 17채`: 길이 17, 두 lot이 같은 (x,zOff)를 갖지 않는다.
  - `모든 문까지 걸어간다` (집 1채·17채): `guestSpot('promo')`에서 모든 `doorStep`, 6개 `shopDoor`, 뒷산 꼭대기, 포장마차, 방파제 끝까지 `findTownPath` 끝점이 0.3 안.

  - `가게 건물은 문으로만`: 각 가게 칸 가운데 (건물 안) 막힘.
  - 기존 마당 좌표 왕복·손님 첫 자리·공원 테스트는 그대로 통과해야 한다.
